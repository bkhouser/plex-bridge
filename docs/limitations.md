# Known limits and unverified steps

- History enrollment is an explicit operator-established cloud-to-local binding. Plex's local account response lacks a cloud foreign key. API checks validate the enrolled tuple, but cannot detect identical local ID/name reuse after account recreation. Re-enroll after server restoration or account recreation.
- Some managed/shared Plex tokens may not be accepted by the cloud self-identity endpoint. These fail closed. No owner-session fallback is used for their view state.
- Playback events may be unavailable, permission-limited or historically incomplete. An unwatched flag does not prove a title was never seen. Manually marking watched need not produce an event; clearing watched does not erase imported events.
- Legacy events without verified selected-library membership remain excluded unless individually enrolled under an active owner-confirmed historical mapping. Schema-3 recovery requires separately supplied operator approval for exact historical cohorts; it preserves original identity and leaves current-item linkage unknown. Other libraries remain excluded. Ordinary full sync does not create historical mappings. See [historical recovery and revocation](historical-recovery.md) and [schema-2 activation](cache-upgrade-v2.md).
- Public-rating provider/metric classification is conservative. Unknown sources remain in the raw `public_ratings` list and are omitted from critic/audience aliases and sorts. A fresh Plex cache does not establish that an upstream IMDb/TMDB/Rotten Tomatoes score is current.
- Incremental synchronization rescans catalog metadata and state for correctness; it is not a metadata-delta-only protocol. It retrieves history with a two-day overlap. Older backfills require `sync --full`. Imported history is retained even if Plex later prunes it.
- PMS pagination lacks an atomic server snapshot. Obvious page/total inconsistencies are rejected; same-count concurrent changes can need a later refresh.
- Canonical deduplication needs a modern Plex GUID. Legacy/local GUIDs and missing identifiers remain separate rather than risking false merges. Edition-specific watched state is retained. Unwatched search conservatively excludes a title when any verified duplicate is currently watched.
- Availability matching normalizes Unicode, case, punctuation and whitespace, with optional exact year. It does not guess misspellings, translated titles or release-year offsets. A cache miss is not a global statement of nonexistence.
- Genre/person filters use exact case-insensitive metadata values. Keyword matches cannot prove intelligence, realism or writing quality. ChatGPT makes final recommendations. No persistent recommendation-exposure ledger is maintained.
- Most summaries count physical entries; duplicate copies can weight behavioral signals. They are explicitly labeled. Results are bounded; large histories require pagination.
- OAuth verification is tested with generated RSA keys. Production requires provider-issued RS256 RFC 9068 access tokens (`typ=at+jwt`). The project does not run an authorization server or support opaque-token introspection. Immediate provider-side JWT revocation is not implemented; use short expirations and stop the service to revoke access immediately.
- Local bearer mode is for trusted-machine testing only. Loopback binding does not authorize remote forwarding. Switch to OAuth before using a tunnel/proxy.
- Single-process rate limiting and SQLite write serialization suit one personal user. A long sync can delay feedback writes. Files and backups require operating-system access controls; database encryption is not provided.
- The test runtime emits one Starlette deprecation warning about its httpx-based TestClient. The official MCP client still uses httpx. This warning does not indicate a test failure.
